Please review and address these issues in the `txschools` R package.

## 1. Generic TAPR tables can mislabel real values as masked

File: `R/tapr_semantic.R`

`coerce_tapr_generic_value()` sends every generic TAPR table cell through
`parse_tapr_values()`. The fallback logic in `parse_tapr_values()` treats
non-letter, non-numeric strings as suppression markers.

Example confirmed behavior:

```r
txschools:::parse_tapr_values("2019-20")
```

returns `masked = TRUE`, but `"2019-20"` is a school-year label, not a TEA
suppression value.

This likely affects generic semantic TAPR outputs such as STAAR, graduation,
staff, finance, etc. The fix should probably make suppression detection
narrower or context-aware, so values like `"2019-20"` remain ordinary text
while true markers like `"< 1%"`, `"*"`, `"."`, `"?"`, etc. are still
preserved as masked.

## 2. Vignette checking fails

File: `vignettes/getting-started.Rmd`

The setup chunk sets:

```r
eval = identical(Sys.getenv("TXS_LIVE"), "true")
```

but `R CMD check` still ran vignette code and failed when
`txs_list_years("tapr")` tried to write to the user cache:

```text
cannot open file .../txschools/_meta/years_tapr.yml: Operation not permitted
```

The vignette needs stronger protection for live/cache-writing code, likely by
guarding inside chunks, using a temporary cache directory during vignette
execution, or excluding live chunks from tangling/check execution.

## 3. `file_format = "html"` silently ignores `data_type`

File: `R/tapr.R`

In `txs_get_tapr_file()`, the HTML branch always calls:

```r
txs_get_tapr_html_report(..., data_type = "rates", ...)
```

So a contradictory user request like:

```r
txs_get_tapr_file(..., file_format = "html", data_type = "advanced")
```

does not error. It silently uses `"rates"`.

The validation inside `txs_get_tapr_html_report()` for non-rates `data_type`
is effectively unreachable from the public function. The public function
should either validate before dispatching or preserve the user-supplied
`data_type`.

## 4. Requested semantic pages can fail into empty tables without warning

File: `R/tapr_semantic.R`

In `fetch_tapr_semantic_pages()`, fallback page download errors are swallowed:

```r
error = function(e) NULL
```

Then `extract_tapr_semantic_pages()` leaves requested datasets empty if the
page was unavailable.

This means a TEA route change, temporary download failure, or parser failure
can look like legitimate zero-row data. For explicitly requested datasets,
missing pages should probably warn or error with enough detail to distinguish
"not available" from "available but empty".

## 5. Percent numeric conventions are inconsistent

Files: `R/mask.R`, `R/tapr_semantic.R`

`mask_strip()` parses `"97%"` as `97`, preserving the printed scale.

But semantic TAPR parsing via `parse_tapr_values()` converts percents to
proportions, so `"90%"` becomes `0.9`.

Both conventions are defensible, but mixing them across APIs is risky for
visualization/modeling. The package should document this very explicitly or
standardize the convention across tidy outputs.
